# Active Care · 认知症主动安全伴护原型

> **仓库状态**：目前本仓库只包含使用说明，尚未上传 `web/`、`vision/` 等项目源码。下文安装与启动步骤需要源码补齐后才能执行。

一个用于工业设计研究、交互验证与项目展示的本地软件原型：通过电脑摄像头和 YOLO 姿态模型获取人员与关键点信息，结合区域、持续时间和环境模拟输入，完成风险事件、渐进式干预、人工反馈与处理记录的闭环。

**核心原则：风险程度与干预方式分开判断，采用最低必要干预。**

> 本项目不是经过临床验证的医疗或安全监护产品。动作与疑似跌倒判断可能误报、漏报，不能替代照护者、独立烟雾报警器或紧急服务。请勿为了测试而真实摔倒，也不要使用本原型控制真实危险设备。

## 目前能做什么

| 模块 | 已实现内容 | 数据来源与边界 |
| --- | --- | --- |
| 人员与姿态 | 人员框、置信度、17 个身体关键点、骨架 | 本机 YOLO11n-pose 推理；人物编号是临时跟踪编号，不是身份识别 |
| 动作候选 | 站姿、屈膝 / 坐姿、躯干倾斜、横卧、单手 / 双手举起、画面内位移 | 关键点几何与连续帧规则；不判断意图，不可靠区分坐下与下蹲 |
| 疑似跌倒 | 先有站立证据，再出现快速下降与持续横卧候选，生成核查事件 | 演示规则，不判断意识或伤情；后续站立也不会自动解除 |
| 区域监测 | 手动选择观察对象、划定最多 3 个矩形区域、进入 / 离开确认、停留计时 | 根据脚踝中点做二维投影判断；不报告实际米数 |
| 环境面板 | 温度、湿度、烟雾、燃气、门磁，以及采样暂停 / 故障状态 | **全部是模拟输入**；门磁只显示状态，不推断人员外出 |
| 风险与干预 | 独立事件、优先级、支持方式预设、I0—I4、执行回执 | 规则决策；网页提醒和求助可用，实体控制与手机通知未接入 |
| 反馈与记录 | 接手、代填回应、拒绝、求助、误报标注、核查、结束事件、JSON 导出 | 本次页面会话内保存；刷新后重置 |
| 画面体验 | 实时预览 / 识别画面切换、左右翻转、分段耗时、过期提示 | 识别目标上限 15 FPS，实际取决于设备；不将旧骨架叠到实时视频上 |

**AI 与规则的分工：** YOLO 负责检测人物和关键点；动作候选、区域停留、风险与干预由代码中的明确规则处理。项目没有从零训练大模型，也没有训练针对认知症患者的动作分类模型。

## 安装与启动

### 1. 获取项目

克隆仓库并进入项目目录。请先确认仓库中已包含 `web/` 和 `vision/` 源码。

```bash
git clone https://github.com/limark-00/yl_1.git active-care
cd active-care
```

也可以下载仓库 ZIP 并解压，然后在终端进入包含 `web/`、`vision/` 和本 README 的项目根目录。

### 2. 安装视觉后端与模型

在项目根目录执行：

```bash
python3.12 -m venv vision/.venv
vision/.venv/bin/python -m pip install -r vision/requirements.txt
vision/.venv/bin/python vision/download_model.py
```

下载脚本从官方来源获取 `yolo11n-pose.pt`，并核对大小和 SHA-256。模型存放在 `vision/models/`，校验值记录在 [model.sha256](vision/model.sha256)。不要跳过校验，也不要直接加载来源不明的权重。

`requirements.txt` 来自开发机的 macOS arm64 环境。若在其他系统上出现不兼容，请结合 [requirements.in](vision/requirements.in) 为目标平台重新建立依赖环境并测试；不要把跨平台安装当作已经验证通过。

### 3. 安装网页依赖

```bash
cd web
pnpm install --frozen-lockfile
cd ..
```

如果提示锁文件不兼容，先检查 pnpm 版本和错误信息。不要通过删除锁文件来掩盖安装问题。

### 4. 启动两个服务

**终端 A：** 从项目根目录启动视觉服务。

```bash
cd vision
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8001 --no-access-log
```

**终端 B：** 从项目根目录启动网页。

```bash
cd web
pnpm dev --port 3000
```

打开 **[http://localhost:3000](http://localhost:3000)**，点击 **“开启摄像头与识别”** 并允许权限。

视觉服务健康检查：

```bash
curl http://127.0.0.1:8001/health
```

模型准备好后，返回内容中的 `status` 应为 `ready`。没有启动视觉服务时，仍可演示网页上的环境模拟、风险与干预流程。

> 请保留前端 `3000`、后端 `8001` 这两个端口。当前来源校验与前端地址配置按它们实现。如果前端因端口占用切换到 `3001`，摄像头功能不会按原配置工作。不要将视觉服务绑定到 `0.0.0.0` 或暴露给公网。

### 可选：macOS 启动脚本

首次安装完成后，可在项目根目录运行：

```bash
bash ./启动本地伴护.command
```

也可以尝试双击该文件。脚本不代替首次依赖安装；运行时请保留终端。按 `Ctrl+C` 会停止脚本自己启动的服务，不会结束此前已经运行的服务。手动分开启动的两个服务，应分别在各自终端中停止。

## 使用教程

### A. 摄像头、动作与画面方向

1. 固定电脑，保证光线充足，让肩部、髋部、腿部和脚踝尽量完整入镜。
2. 点击“开启摄像头与识别”。默认的 **实时预览** 不等待 YOLO 结果。
3. 切换到 **识别画面 · 人物与骨架**，查看人员框、关键点和动作候选。框、骨架与背景来自同一分析帧。
4. 尝试安全的举手、坐下、起身和缓慢移动。动作需要满足连续证据条件，不会在单帧出现时立刻确认。
5. 若左右方向不符合需要，切换 **左右翻转**。图像、人物框、骨架、区域和划区输入会同步换算，文字不会反写。

左右翻转只改变显示与输入换算，不改变送入 YOLO 的原始图像坐标，也不改变已保存区域对应的位置。实时模式不显示滞后的骨架、脚踝点或区域进入颜色；要查看这些对应关系，请使用识别画面。

页面会显示分析帧率、编码耗时、本机请求往返、模型耗时、采集至结果和结果年龄。**请求往返已经包含模型推理，不要将两者重复相加。** 时间从浏览器复制画面开始，不包含摄像头曝光或硬件缓冲。

### B. 选人、划区与停留提醒

1. 摄像头开启后，在“观察对象”中手动选择人物编号。系统不会自动认定谁是患者。
2. 点击“新增地面区域”，拖动框选地面，也可输入左 / 上 / 右 / 下边界百分比。
3. 填写区域名称与停留阈值：**5—120 秒**，最多 3 个区域。区域宽、高至少各占画面的 6%。
4. 保存后点击“开始区域监测”。如电脑或机位移动，先暂停，重新核对区域并确认机位。
5. 观察对象进入区域并被连续确认后开始计时。达到阈值，生成摄像头来源的 **L2 区域停留事件**。
6. 同一对象被确认在区域外后进入恢复观察；累积 **5 秒有效、稳定的区域外证据**，才可以结束事件。

请框选灶台前、门口等**地面范围**，不要将灶台台面当作地面位置。当前没有距离标定，区域不能用于证明人物距离危险物体多少米。

遮挡、脚踝点不足、暂停、换人或停止摄像头都不会被当作“已经离开”。新对象不会继承旧对象的事件，也不能替旧对象解除警报。

### C. 环境模拟与渐进式干预

无需摄像头也可以按以下流程演示：

1. 点击“演示温度异常”：先创建 **L1 / I0**，持续 5 秒后进入 **L2 / I1**。
2. 保持页面可见，不填写反馈。提示成功呈现后等待 20 秒，异常仍有效时增加支持；I1 可以转 I2，再转 I4。风险不会仅因未回应而升高。
3. 点击“确认接手”，或代填“已回应 / 拒绝提醒 / 请求帮助”。这些动作有独立记录，不直接消除异常。
4. 点击“恢复输入默认值”。稳定恢复 5 秒后，在事件中心结束事件。
5. 将支持预设改为“需要图示支持”，再触发新事件：同样的 L2 可以从 I2 开始。预设只作用于之后的新事件。
6. 点击“演示烟雾报警”：直接进入 **L4 / I4**，不会先等待多轮提醒。其他正常读数不能压低它的优先级。

所有环境读数、报警状态和阈值均用于演示，不是实际传感器结果或医疗、消防标准。

### D. 疑似跌倒与人工处理

疑似跌倒候选进入统一事件中心，直接创建 **L3 / I4 网页核查请求**。它覆盖画面中可识别的人物，不限于区域监测选中的对象。

- 恢复站立、停止摄像头、确认接手或代填已回应，均不自动解除疑似跌倒事件。
- 误报标注只是标注，不是结束事件。
- 只有实际核查后，填写核查说明并选择“记录核查并结束”，才记录人工结束。
- 延迟返回的候选会明确标为历史证据，不冒充当前实时状态。

**不要安排真实摔倒来验证。** 当前没有视频上传 / 回放入口；测试规则可以运行自动化测试，但测试通过不代表已经验证真实跌倒识别准确率。

### E. 导出记录

点击“决策记录”右上角的下载按钮，导出 JSON 会话报告。内容包括策略、数据来源、事件、人工反馈、执行回执、状态转移、区域配置与区域记录。

导出不包含原始视频、图像、关键点序列或后端授权令牌。普通动作变化记录仍单独保留在当前视觉面板内，并非完整视频轨迹导出。**刷新页面会清空本次会话**；需要的记录请先导出。当前没有 JSON 导入恢复功能。

## 风险与干预如何工作

### 风险等级与干预类别分开

风险 L0—L4 是原型中的策略标签，不是医学分级或危险概率。输入不足时使用 `UNKNOWN`，不能当作 L0。

| 干预 | 当前真实能力 |
| --- | --- |
| I0 观察 | 收集证据、记录状态，不主动提示 |
| I1 提醒 | 网页文字提醒；当前不播放语音 |
| I2 引导 | 网页分步骤提示与图示；不生成经过验证的安全路线 |
| I3 保护请求 | 仅 L3 / L4 可手动演示保护建议，回执为 `simulated`；不关火、不锁门、不限制行动 |
| I4 求助 | 创建网页内照护者待处理请求；不发送手机通知或联系外部人员 |

I0—I4 不是必须逐级走完的阶梯。紧急事件直接请求协助，I3 不是 I4 的前置条件；拒绝提醒也不构成限制理由。

### 状态、执行与反馈

事件阶段包括：

```text
CONFIRMING       观察确认
INTERVENING      等待干预呈现
WAITING_RESPONSE 等待回应
ESCALATED        需要协助
RECOVERING       恢复观察
CLOSED           已结束
```

总览显示 `UNKNOWN / SAFE / MONITORING / LOW_RISK / MEDIUM_RISK / HIGH_RISK / EMERGENCY / RECOVERING`，由事件与观测质量派生。`SAFE` 的界面文案是“当前未见目标异常”，仅指当前有效观测范围，不承诺人员安全。

干预执行记录区分 `requested / executed / simulated / failed / unavailable`。只有提示在可见网页中呈现后，才记网页执行回执并启动反馈计时；**网页已呈现不代表患者看见、听见或理解**。

“确认接手”“人工代填反馈”“误报标注”“结束事件”是不同操作。观测丢失会保留事件；普通事件需要有效恢复证据，疑似跌倒需要人工核查。结束一个事件不会清空其他并发事件。

## 常见问题

| 问题 | 检查方法 |
| --- | --- |
| 网页打开了，但连接不到 YOLO | 确认终端 A 仍在运行，检查 `127.0.0.1:8001/health` 是否返回 `ready` |
| 摄像头被拒绝 | 检查浏览器与系统摄像头权限；使用 `http://localhost:3000`，不要从远程地址打开 |
| 摄像头无法读取 | 检查是否被其他应用占用，停止占用后重新开启 |
| 页面端口变成了 3001 | 原 3000 端口被占用；确认占用来源并恢复本项目的 3000 配置，不要直接结束不明进程 |
| 预览顺畅，但骨架更新慢 | 两者刷新链路不同；查看编码、请求往返、模型耗时与结果年龄。15 FPS 仅是分析上限 |
| 左右方向不合适 | 切换“左右翻转”；不要只对视频单独加 CSS 镜像，否则会与区域坐标不一致 |
| 没有人物 / 动作未知 | 调整光照、机位、距离，减少遮挡，让主要关节完整入镜；未知不代表安全 |
| 区域不计时 | 确认已选人、保存区域并开始监测；双脚踝需要有效，机位变化后重新确认 |
| 停止摄像头后事件还在 | 这是预期行为：丢失观测不等于风险解除，请按事件的恢复或人工核查流程处理 |
| 模型缺失或校验失败 | 运行 `vision/download_model.py`，检查网络与错误信息，不绕过校验 |
| 页面切到后台后停止识别 | 这是主动停止采集的设计，返回页面后需重新开启 |
| 刷新后记录消失 | 当前只保留会话内存，刷新前先导出 JSON；暂不支持导入恢复 |

报告问题时，请提供操作系统、Python / Node / pnpm 版本、复现步骤、相关错误文本，以及可复现的页面指标。不要直接提交带有真实患者信息的截图、视频或导出记录。

## 数据与隐私

- 摄像头需主动开启并授权；不请求麦克风。
- 浏览器将视频帧发送到 `127.0.0.1:8001`，视觉推理在本机执行，不将摄像头画面上传云端。
- 当前推理链路不将原始图像 / 视频写入磁盘；停止或进入后台会停止摄像头采集。
- 不识别姓名或真实身份，不判断认知程度，也不从动作推断是否理解提醒。
- 人工说明可能包含使用者自行填写的信息。请使用虚构演示对象，不填写真实患者姓名等敏感数据。
- 页面、日志与报告会区分模拟环境和摄像头证据。未配置手机通知或硬件控制，界面不会声称已经联系家属或关闭设备。

上传代码到 GitHub 不会自动部署整个系统。当前项目需要本机 Python 服务，不能仅靠静态网页托管运行 YOLO 摄像头功能。

以下主要供仓库维护者首次发布时使用；仅下载运行项目的使用者可跳过。

1. **以项目根目录为仓库根目录**，包含 `web/`、`vision/`、安装清单、锁文件、下载脚本与本 README。
2. 核对上文的仓库地址，补充项目作者与适用的许可证信息。
3. 检查是否存在独立的 `web/.git`。若有嵌套仓库，直接添加根目录可能不会把前端源码作为普通文件上传。先备份并确认要保留的提交历史，再选择统一仓库或正式子模块方案；不要未经确认直接删除 `.git`。
4. 不提交虚拟环境、依赖目录、模型权重、缓存、构建产物、密钥或真实演示数据。
5. 上传后检查 GitHub 中能否正常查看 `web/components/vision-panel.tsx`、`vision/app.py` 等源码，而不只是一个不完整的子仓库链接。
6. 从一个新的目录重新克隆并按本文安装，确认仓库没有依赖开发机上未提交的文件。
