# 主动伴护 · 本地原型

已完成第 01–05 部分的本地演示框架：环境模拟、YOLO 姿态与动作候选、区域停留、统一风险事件、渐进式干预、执行回执、患者反馈闭环、反馈后二次 AI 判断和会话报告。

**摄像头延迟优化已接入：实时预览独立于识别刷新，分析循环目标上限从约 3.3 提升到 15 FPS，新增左右翻转与分段耗时显示。真实机位的效果仍需现场验证，15 FPS 是目标上限，不是保证值。**

## 在这台电脑上使用

依赖与模型已放在项目本地。两个服务运行时，直接打开 **http://localhost:3000**，点击 **“开启摄像头与识别”**，由你允许摄像头权限。若内嵌预览无法授权，可在电脑浏览器中打开同一地址。

服务关闭后，可双击 `启动本地伴护.command`，或在项目根目录执行：

```sh
bash 启动本地伴护.command
```

关闭 / 隐藏网页会停止摄像头；要继续需重新手动开启。停止脚本会停止它启动的服务，不会结束之前已经运行的服务。

## 能看到什么

| 能力                                      | 实现与边界                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------------- |
| 人员框 / 检测置信度                       | YOLO11n-pose 真实推理，最多 8 人；置信度不是动作准确率                      |

## 如何试用

1. 固定电脑，保证光线充足；退后让肩、髋和腿部尽量完整入镜。
2. 开启摄像头，默认显示“实时预览 · 低延迟”。点击“识别画面 · 人物与骨架”查看人物框与黄色关键点。统计里的帧率是分析结果帧率，不是摄像头帧率。
3. 站立、举起一只手、举起双手并各保持约 1–2 秒；查看标签和动作记录。
4. 在安全位置坐下、起身、缓慢移动，观察候选标签。遮挡或移出画面后，应显示未检测 / 未知，而不是“安全”。
5. 停止摄像头，检查摄像头使用指示灯关闭。已有疑似跌倒事件不会因停止采集而自动清除，需在事件中心填写实际核查说明后结束。

“实时预览”直接显示摄像头，不等待模型，也不叠加旧骨架或旧脚踝点。“识别画面”显示**完成推理的同一帧**，人物框、骨架与画面一致。两种模式均继续后台识别和事件判断。单帧请求超过 6 秒会停止摄像头并清除旧结果。

## 摄像头延迟与左右方向

- **采集与显示**：请求摄像头约 30 FPS；实际由设备 / 浏览器决定。新帧回调驱动分析，目标上限 15 FPS，只有一个分析任务在运行；忙碌时跳过帧，完成后等待新帧，不处理积压队列。兼容模式检查视频时间是否前进，不重复分析冻结画面。
- **保持识别质量配置**：仍使用 YOLO11n-pose、CPU、640 模型输入、最大 640×480 JPEG 和原置信度 / 动作持续阈值。没有通过缩小模型输入或放宽跌倒规则来换取速度。
- **左右翻转**：默认将旧版方向水平反转，可在工具栏关闭。翻转只影响显示与划区输入换算；原始视频仍按原方向送入 YOLO。画面、框、骨架、区域、观察点同步变换，文字不反写。切换方向不改变已保存区域对应的物理位置或事件归属。
- **模式区别**：实时模式显示中性的区域边界，不将上一次识别的进入颜色或脚踝位置当作实时结果。要看识别对象与区域位置对应，请切换“识别画面”。
- **性能指标**：分别显示 JPEG 编码、本机 HTTP 往返、模型耗时、浏览器采集至结果、结果年龄。往返耗时已经包含模型推理，不能将两者再次相加。计时从浏览器复制画面开始，不包含摄像头曝光、硬件缓冲或屏幕刷新延迟。
- **过期与停止**：结果年龄超过 500ms 提示滞后；既有区域证据超过 3.5 秒仍按未知处理。摄像头连续 3 秒无新视频帧会停止，且与推理等待独立。停止 / 后台 / 请求失败会取消帧回调与采样计时器，迟到结果不能恢复采集。

## 第 03 部分：区域停留与干预

1. 开启摄像头，保持电脑固定，让双脚踝尽量入镜。
2. 点击 **新增地面区域**，在画面拖动框选地面范围，也可输入左 / 上 / 右 / 下边界百分比。不要把灶台台面当成地面；此处是二维投影判断。
3. 填写名称和 **5–120 秒**停留阈值（默认 10 秒），保存。最多 3 个矩形区域。
4. 在“观察对象”选择当前人物编号，点击 **开始区域监测**。不会自动把某个人当成患者。
5. 让所选对象进入区域：连续至少 0.6 秒、2 帧确认位置后计时，达到阈值创建 **摄像头来源的 L2 事件**。按新事件的能力预设进入 I1 或 I2；提示在可见网页呈现后开始回应窗口（简短提醒 20 秒、图示支持 15 秒），超时且异常证据仍有效才增加支持，最终 I4 网页求助。
6. 同一对象被连续确认在区域外后，进入恢复观察；稳定 5 秒才可在事件中心结束事件。仅“确认接手”或“误报标注”不会消除异常。

普通进入 / 离开记录位于视觉面板内；超过阈值的事件进入统一事件中心，与模拟温湿度 / 烟雾事件独立处理。烟雾 L4 仍优先，不会被区域 L2 降低。

### 观测丢失与人工核查

- 计时以**采集画面的时间**为依据，界面时钟和等待模型返回的时间不会自动增加停留时长。
- 画面返回已超过 3.5 秒、相邻采集间隔过长、对象丢失或脚踝置信度不足时：显示未知、停止累计连续停留；不会据此认定已经离开。
- 暂停、换人、删区域不会关闭已有事件。新对象不继承旧对象的事件，也不能替旧对象解除警报。
- 摄像头停止、会话切换或尺寸变化会解除临时绑定。重启后需要重新选择人物，并点击“确认当前机位与区域”。系统无法可靠自动判断电脑是否被移动，移动电脑后应主动暂停并重新划区。
- 如旧对象已无法继续观测，**实际人工核查后**可在其事件卡片展开“视觉证据中断后的人工核查”，填写核查情况并记录结束。日志会明确这是人工处置，不是系统确认安全；仍有有效异常证据时不能走此入口。
- 所有区域、人物选择和记录仅在当前网页会话中保留；刷新重置。JSON 导出包含区域配置 / 记录和来源明确的事件，不包含视频或后端会话令牌。

新增代码位于 `web/lib/zones.ts`（区域时序规则）、`web/components/zone-editor.tsx`（编辑与显示）、`web/components/use-zone-monitor.ts`（视觉证据适配）、`web/tests/zones.test.ts`（区域及干预集成测试）。

## 第 04 部分：完整流程框架

### 现在串通的流程

`真实摄像头 / 模拟环境 → 来源明确的证据 → 独立风险事件 → 个体支持策略 → 网页呈现回执 → 患者反馈 → 证据复核 / 再决策 → 恢复 / 人工结束`

- **统一事件**：温湿度、烟雾、燃气、输入故障、区域停留与疑似跌倒均进入事件中心。疑似跌倒直接 L3 / I4；烟雾、燃气直接 L4 / I4。多人跌倒候选按本次摄像头会话与人物编号隔离；区域停留仍只针对人工选定对象。
- **跌倒核查**：候选不是伤情判断。重复帧不重复创建；后续站立、移出画面、接手、代填已回应或误报标注均不解除。必须填写实际人工核查说明。过期返回的跌倒候选作为“历史候选 / 当前观测未知”保留，不伪装成实时证据。
- **状态机**：事件阶段包含 CONFIRMING / INTERVENING / WAITING_RESPONSE / ESCALATED / RECOVERING / CLOSED。总览的 UNKNOWN / SAFE / MONITORING / LOW_RISK / MEDIUM_RISK / HIGH_RISK / EMERGENCY / RECOVERING 由事件和观测质量派生，不另存一套患者诊断结论。I4 求助不必提升 L 风险。
- **观测质量**：VALID / DEGRADED / UNKNOWN 单独显示。SAFE 的界面文案是“当前未见目标异常”；要求环境模拟有效、人工选定人物姿态可用、区域已开启且位置已确认。摄像头未开或对象丢失不能得到 L0。
- **执行结果**：动作记录包含 action_type、requested_at、completed_at、channel、status 和 result。先 requested，提示组件在可见页面挂载后才回传 executed；仅代表文字已在网页呈现，不代表患者看到或理解。回应窗口从回执开始：简短提醒预设 20 秒，图示支持预设 15 秒。输出失败转为网页求助，不归咎于患者未回应。
- **I3 与 I4 并行**：L3/L4 的事件可点击“模拟 I3 保护请求”，仅记录 simulated，不降级或替代 I4，不控制设备。低风险 / 拒绝提醒不能授权 I3。“检查手机通知接口”返回 unavailable，不发送任何消息。相同接口请求不会重复执行。
- **会话导出**：决策记录右上角下载 JSON（格式 v5），包含策略、来源、当前证据摘要、AI建议及历史、规则融合、执行回执、反馈轨迹、状态转移和区域记录。无图像、关键点序列、后端授权令牌或人工文字原文；当前模块不提供导入 / 回放，也不自动持久保存。事件摘要和人工核查说明仍可能包含你自行填写的信息，请勿填写真实患者姓名等敏感内容。

### 面试演示建议

1. 在“系统框架”解释哪些来自 AI、哪些来自规则、哪些仍为模拟；摄像头未开启时总览显示观测不足。
2. 用区域停留展示真实视觉证据；用温度模拟展示相同 L2、不同预设从 I1 / I2 开始。
3. 查看事件卡的反馈倒计时，记录“已按提醒行动”，说明回应仍需现场证据验证；保持异常 10 秒展示 I1 → I2 再决策，或恢复输入展示 RECOVERING。展开反馈轨迹与 AI 历史说明旧轮次不会污染新结果。
4. 模拟烟雾触发 L4 / I4，检查其他正常读数不会压低它；模拟 I3 和检查手机接口都不会声称设备已执行。
5. 恢复模拟输入，稳定观察 5 秒后结束事件，导出 JSON 说明决策依据。不要为验证跌倒而实际摔倒。

## 第 05 部分：患者反馈闭环与渐进式再决策

事件卡现在把“患者反馈”和“照护者接手”分开。患者反馈包括已按提醒行动、已回应正在处理、复核后风险仍在、拒绝提醒和主动求助；均由演示者代填，不是语音理解或意图识别。

- 每条反馈绑定当轮网页干预的请求键，旧轮次的迟到反馈不能覆盖新轮次。
- 未呈现的提示不能记录“已回应”；主动求助可以随时进入 I4，但不会自动提高风险等级。
- 无反馈只在提示实际呈现、观测仍有效且异常持续时由计时器产生。I1 无回应进入 I2，I2 / I3 无回应进入 I4，不因无回应进入 I3 限制动作。
- “已按提醒行动”不会直接关闭事件。系统继续复核 10 秒：证据恢复则把该反馈标记为已验证并进入 RECOVERING；证据仍异常则增加支持并开始新一轮。
- 拒绝提醒只记录自主选择，不自动推断失能，也不授权限制行动。照护者点击“确认接手”后暂停自动未回应升级，但继续更新风险证据。
- 每次反馈会更新统一事件上下文和请求版本。旧上下文 AI 结果只存档、不融合；V3.1 按新回应与前次干预重新判断。确定性状态机先执行，模型仍不能降低规则安全下限。

这一版本不需要重新训练模型：V3.1 数据已经包含能力、回应和前次干预字段。当前闭环的升级规则仍是演示策略，反馈也不是来自真实患者数据，不能据此声称个性化照护有效。

## 架构与文件

浏览器摄像头 → 缩放 JPEG → 本机 FastAPI → YOLO 人物 / 关键点 → 短时跟踪与动作规则 → 网页同帧可视化。

- `web/components/vision-panel.tsx`：权限、视频生命周期、串行发帧、动作与核查提示。
- `web/lib/vision.ts`：接口校验、骨架绘制、错误说明。
- `web/lib/vision-runtime.ts`：新帧驱动、单任务调度、冻结检测和显示坐标变换。
- `vision/benchmark_transport.py`：不使用摄像头的本机 HTTP 节奏测试。
- `vision/app.py`：本地接口、来源限制、会话隔离、大小 / 顺序校验。
- `vision/detector.py`：模型加载、CPU 推理、关闭 Ultralytics 联网 / 同步。
- `vision/pose_logic.py`：可单独测试的连续动作候选规则。
- `web/lib/care/engine.ts`：统一事件状态机、风险与干预选择、人工处理。
- `web/lib/care/camera.ts`：区域 / 姿态结果到事件核心的无图像适配器。
- `web/lib/care/overview.ts`：总览状态与观测质量派生。
- `web/lib/care/outputs.ts`：干预内容、回执契约与未接通接口结果。
- `web/lib/care/session.ts`：白名单会话报告。
- `web/components/intervention-output.tsx`：网页提示呈现回执、执行历史、接口演示。
- `web/components/feedback-loop-panel.tsx`：回应倒计时、反馈操作、证据复核与多轮轨迹。
- `web/components/framework-panel.tsx`：模块运行状态与状态转移记录。

## 文字决策模型实验

`decision_model/`现在包含三组可对照实验：TF-IDF基线、冻结MacBERT特征的Event Transformer，以及解冻MacBERT最后两层的联合微调。困难版V3数据共8,500条，主训练集6,000条；输入文字不显示L/I答案代码，训练、验证和测试按事件定义隔离。

V3首次部分微调揭示了I3在严格测试集上无法泛化。保留该检查点后，V3.1新增42个I2/I3/I4边界事件、风险等级辅助头、有序安全损失、欠干预指标，以及以干预任务为主的安全加权模型选择。两个版本使用不同输出目录，可用于完整的消融对照。

运行部分微调：

```sh
bash decision_model/run_partial_finetuning.command
```

运行V3.1安全边界实验：

```sh
bash decision_model/run_partial_finetuning_v31.command
```

脚本会先确定性生成V3，再开始训练。结果写入`decision_model/outputs/partial-macbert-时间/`，其中`best_delta.pt`只保存解冻层和任务网络。该模型仍然学习合成策略，不是经过临床验证的照护模型。具体数据限制、参数和内存调整见`decision_model/data/v3/README.md`与`decision_model/training/README.md`。

### 在网站中试用V3.1

完成V3.1训练后，按正常方式启动两个本地服务。启动脚本会分别报告视觉服务和AI检查点状态；模型缺失时摄像头与规则引擎仍能降级运行。网页侧栏打开“AI文字决策”，可选择示例或输入自己的多行事件文字，再点击“运行真实模型”。首次请求会延迟加载MacBERT和55 MB增量权重，后续请求直接复用内存模型。

页面同时显示模型原始五任务输出、置信度、类别概率和一致性校验后的演示输出。厨房、卫生间、卧室、客厅、入户门区域和阳台是V3.1训练场景；可以输入其他地点，但属于分布外测试。非L0/I0的人工文字结果会作为“人工文字”事件进入统一事件中心，须填写实际核查说明才能结束。

环境与摄像头事件创建后会自动转换为同一文字结构，并由串行队列调用V3.1。患者反馈会增加上下文版本，补充当前回应和前次干预，再次进入队列；旧版本结果只存档。事件卡同时显示规则基线、AI建议和融合结果：AI可以增加风险或支持，但不能降低烟雾、燃气、跌倒等既有规则下限；模型拒绝判断、返回过晚或服务不可用时只记录状态，反馈状态机和规则流程继续运行。所有输出仍只作用于网页，不触发真实设备、手机或外部求助。

输入文字不会写入磁盘。页面会话内只保留事件摘要，JSON导出主动去除人工输入原文。默认自动选择`decision_model/outputs/`中最新的V3.1检查点；可通过`CARE_DECISION_CHECKPOINT`指定另一运行目录或`best_delta.pt`。推理按训练时记录的MacBERT版本从本机缓存加载，不在现场演示时联网更新基础模型。

区域停留和疑似跌倒均接入统一干预引擎。不会把“举手”自动当成求助，也不把人物编号当作真实身份。总览状态是原型内的派生标签，不是患者安全诊断。

## 隐私、授权与模型来源

只请求视频，不请求麦克风。JPEG 仅在浏览器与本机服务之间传输，不写磁盘、不上传云端。会话编号临时生成，空闲 120 秒过期；后端不识别姓名、面孔身份、认知能力或疾病。环境卡片仍明确标注模拟。

模型使用 Ultralytics 的 [YOLO11 Pose 预训练权重](https://docs.ultralytics.com/models/yolo11/)，关键点输出见[官方姿态文档](https://docs.ultralytics.com/tasks/pose/)。这体现的是**使用预训练视觉模型和编写识别系统**，不是从零训练大模型。权重下载校验值记录在 `vision/model.sha256`，仅从官方 GitHub Release 下载。使用 / 分发应遵守项目与权重的[许可说明](https://www.ultralytics.com/license)；本原型不包含商业授权承诺。

远程发布此前受权限策略限制。本阶段依赖本机摄像头服务，未上传代码或摄像头数据，也没有手机通知功能。
