# 合成文字决策数据集 V2

V2用于训练和评估“多事件文字输入 → 干预、警示、人工核查”模型。全部内容为程序生成的虚构场景，不含真实患者数据，也不代表医学、照护、消防或紧急处置标准。

## 规模

- 6个固定场景：厨房、卫生间、卧室、客厅、入户门区域、阳台。
- 每个场景30个事件，共180个事件定义。
- 每个场景25个事件可用于主数据，5个事件只用于分布外测试。
- 主数据6,000个独立组合，每组5种文字表达，共30,000条。
- 主数据按基础组合切分为21,000条训练、4,500条验证、4,500条测试。
- I0～I4各6,000条；同一基础组合的五种表达不会跨分区。
- 另有1,200条未见事件测试，以及1,200条自然类别分布测试。

## 样本类型

| 类型 | 独立组合 | 作用 |
| --- | ---: | --- |
| regular | 3,600 | 常规多事件组合 |
| counterfactual | 1,200 | 成对只改变能力、回应或历史中的一个字段，并要求决策变化 |
| conflict_unknown | 600 | 来源矛盾或信息不足，检查人工核查与拒答 |
| hard | 600 | 4～6条同时发生的困难组合，不允许最后一条覆盖其他事件 |

## 主要标签

训练模型时只把`input_text`送入文字编码器。其他字段用于监督、分析和审计。

- `intervention_level`：I0～I4，五分类主任务。
- `alert_mode`：`NONE`、`PAGE_WARNING`、`URGENT_HELP`，独立警示任务。
- `manual_review`：是否需要人工核查。
- `abstain`：输入冲突时是否应拒绝自动给出最终判断。
- `derived_risk_level`：由事件词条中的L等级确定，只用于一致性检查，不建议作为主要训练任务。

`reason_codes`来自合成策略，不能作为模型输入。否则会直接泄漏标签生成逻辑。

## 数据文件

- `train.jsonl`、`validation.jsonl`、`test.jsonl`：平衡主数据。
- `ood_test.jsonl`：含30个训练阶段从未出现的事件定义。
- `natural_test.jsonl`：I0较多、I4较少的单独评估集。
- `event_catalog.json`：事件、五种表达、上下文词条和标签说明。
- `dataset_summary.json`：精确统计与策略版本。

## 已知限制

五种文字表达由人工编写的基础事件，通过同义词、主体替换和场景化报告句式生成，仍不等于真实用户的自由表达。V2能够支撑模型工程和对照实验，但模型最终只是在学习合成策略。正式展示时应报告合成测试、未见事件测试和自然分布测试三组结果，不能把其中任何一组称为真实照护准确率。
