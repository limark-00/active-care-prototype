# 主动伴护 · 网页端（第 01–04 部分）

认知症主动安全伴护系统的工业设计演示原型。当前实现本机 YOLO 姿态识别、区域停留、环境模拟、网页警报与事件处理闭环；不用于真实照护或消防安全决策。

摄像头和 YOLO 的完整启动、试用步骤见项目根目录 `../README.md`；需要同时运行 `../vision` 本地服务。下文保留环境模拟的操作说明。

## 运行

需要 Node.js 24 和 pnpm。前端使用 React + TypeScript，开发服务基于 vinext/Vite。

```sh
cd web
pnpm install
pnpm dev
```

打开终端显示的本地地址，默认 http://localhost:3000。数据只保存在浏览器内存中，刷新即重置。右侧决策记录可导出 JSON，不包含视频或后端授权令牌；请勿在人工说明中填写真实患者信息。

```sh
pnpm test       # 纯逻辑测试，Node 原生 TypeScript 支持
pnpm typecheck
pnpm lint
pnpm build
```

## 已实现

- 温湿度、烟雾、燃气、门磁的模拟输入；每秒采样，暂停后自动检测过期。
- 同类型的持续异常合并成一个事件，烟雾/燃气报警直接进入 L4 / I4。
- 温湿度持续异常先观察，再按支持预设进入 I1 或 I2；未回应时增加支持，不提高风险等级。
- 有限事件状态：CONFIRMING → INTERVENING → WAITING_RESPONSE / ESCALATED → RECOVERING → CLOSED。失去观测会保留事件；恢复过程中再次异常会返回处理状态。
- 网页动作的 requested / executed / failed 回执；计时从可见网页呈现开始，不把未显示当作患者未回应。
- 疑似跌倒独立 L3 / I4 事件与人工核查，系统模块状态、派生总览状态和观测质量。
- I3 模拟保护建议、手机接口 unavailable 回执；不会执行外部动作。
- 人工接手、代填回应、拒绝提醒、主动求助、误报原因、稳定恢复后结束事件。
- 事件日志、并发事件隔离、输入故障/离线提示、JSON 会话导出。

## 三分钟演示

1. 点击“演示温度异常”：创建 L1 / I0；持续 5 秒后变为 L2 / I1。
2. 提示在可见页面呈现后不填写反馈：20 秒后进入 I2，新的提示呈现后再等待 20 秒进入 I4；风险仍是 L2。
3. 点击“确认接手”：停止未回应升级，但不会消除异常。拒绝提醒也不会触发限制。
4. 点击“恢复输入默认值”：进入恢复观察，稳定 5 秒后才可点击“结束事件”。
5. 选择“需要图示支持”，再次触发温度异常：同样 L2，这次从 I2 开始。
6. 点击“演示烟雾报警”：立即 L4 / I4。暂停采样超过 3.5 秒，原报警继续保留，增加输入异常事件。恢复采样并恢复输入后，分别结束事件。

所有时间和阈值是演示配置，不是医学、消防或舒适度标准。温度触发区间 18–28°C，恢复区间 19–27°C；湿度分别为 30–70% 和 35–65%。恢复区间更窄，避免边界反复开关。

## 视觉与框架边界

- 摄像头、YOLO11n-pose 人员框和关键点已接入；基础动作由连续帧规则判断。真实模型推理与环境模拟完全分开。
- 视频只发往 `127.0.0.1:8001`。需要你主动允许摄像头；不记录视频，不做身份识别。所有结果可能误报 / 漏报。
- 人工选人、矩形地面区域、进入 / 离开、停留与疑似跌倒已接入统一事件中心；来源标注为摄像头。疑似跌倒覆盖画面中全部可识别人物，后续姿态正常也必须人工核查才能结束。
- I1/I2 仍仅网页提示，I3 不操作真实设备，I4 不联系外部人员。环境卡片仍全是模拟数据。
- JSON 导出包含环境 / 视觉事件、干预回执、派生状态转移、区域配置和进入 / 离开记录；普通视觉动作记录单独留在本次页面会话。
- SAFE 仅表示当前有效范围未见目标异常。未配置区域、画面丢失或无有效对象时不能给出 L0。状态与临床安全无等价关系。
- 语音播放、米制距离、真实设备、手机通知、视频回放与跨刷新保存尚未实现。
- 摄像头延迟已进行首轮优化：默认实时预览独立刷新；识别目标上限 15 FPS，忙时丢弃帧，不积压。模型、分辨率与动作阈值不变。实际帧率 / 编码 / 往返 / 模型耗时在页面可见。
- “识别画面”保留同帧人员框与骨架；实时模式不将旧骨架或脚踝点叠到新画面上。左右翻转同步图像、标注、区域与划区输入，原始判断坐标不变。

完整操作与检查步骤参见 [根目录 README](../README.md) 中的“使用教程”和“测试与性能检查”。

## 方向与性能的现场检查

1. 开启摄像头，分别切换“实时预览”和“识别画面”；前者不受识别刷新速度限制，后者显示同帧 AI 标注。
2. 用安全的缓慢举手动作比较左右方向；按需要切换“左右翻转”，人物框与骨架应同步，文字保持正常。
3. 划定地面区域，再切换方向；区域仍应覆盖同一实际位置。数字输入里的左右百分比始终对应当前显示方向。
4. 检查帧率与“采集至结果 / 结果年龄”，并记录自己的机位、浏览器和读数；不可将 HTTP 示例图测试的 14 FPS 当作实际摄像头保证值。
5. 停止摄像头或切换到后台，应停止采集并保留未处理事件。不要真实摔倒来做测试。
