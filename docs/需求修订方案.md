# 认知症患者主动安全伴护系统：原型需求修订方案

更新时间：2026-08-28

本文是需求方案，不代表功能已经开发或通过测试。用于工业设计保研面试，展示视觉 AI 集成、交互设计、规则决策、反馈闭环与工程验证。不用于真实患者安全保障，不替代照护者、独立烟雾报警器或紧急服务。

## 1. 当前范围

- 电脑内置摄像头提供真实视频，使用预训练 YOLO / YOLO Pose 与目标跟踪读取人物位置、轨迹和姿态。
- 网页展示监测结果、环境信息、风险依据、当前干预、事件处理及日志。
- 纳入 L0—L4 风险分级、I0—I4 干预类型、能力档案、反馈闭环和有限状态机。
- 温湿度、烟雾等环境输入在未接硬件时使用明确标注的模拟数据；以后可以换成传感器适配器。
- 当前不接手机推送、短信、电话和真实执行机构，不展开开发排期。
- 不要求自行训练模型。姿态模型负责提取关键点，后续程序负责事件判断；不得宣称预训练姿态模型天然具备跌倒识别能力。[Ultralytics 姿态模型文档](https://docs.ultralytics.com/tasks/pose/)

## 2. 数据来源必须可见

每条输入包含来源、时间戳、有效性及设备/场景标识；视觉输入另外记录检测置信度与跟踪状态。模型置信度不是风险概率。

| 来源 | 含义 | 网页标签 |
| --- | --- | --- |
| camera | 摄像头实际观测，经模型或程序计算 | 实时视觉 |
| replay | 已录视频经过同一识别流程 | 视频回放 |
| sensor | 实际接入且有效的传感器数据 | 真实传感器 |
| simulated | 调试面板或脚本生成的环境数据 | 模拟数据 |
| manual | 患者或演示者/照护者通过界面输入 | 人工输入，并区分角色 |

缺失、过期、断开、遮挡和无法判断必须单独显示，不能当成“正常”。视觉与环境输入混合时显示“混合来源”，保留每条证据的来源。

## 3. 视觉功能

| 功能 | 输入与输出 | 边界 |
| --- | --- | --- |
| 人员出现与离开 | 检测框、跟踪 ID、出现时间、区域退出事件 | ID 不代表患者身份；未检测到不等于已离开 |
| 关注区域接近与停留 | 人体参考点、预设区域、进入/退出时间、停留时长 | 进入不自动等于危险；参考点和区域定义须一致 |
| 门口越线与返回 | 有方向的边界穿越、返回事件 | 不等于识别走失，不做画面之外的位置推断 |
| 疑似跌倒与倒地停留 | 连续姿态变化、相对下降、躯干方向、后续低位姿态 | 不以单帧宽高比判定；不能判断意识、伤情或真实安全 |
| 举手求助 | 约定的持续举手姿态 | 扩展项；不能假设所有患者都能理解或完成，保留按钮 |
| 离床/离椅 | 可见休息区域与姿态变化 | 扩展项；起身本身不是危险，遮挡时不作可靠判断 |
| 反复往返记录 | 连续轨迹中的重复往返 | 扩展项；不推断焦虑、迷路或认知程度 |

运行条件先限定为固定机位、单人、照明较好、相关身体部位可见。电脑换位置后重新配置区域；不承诺跨房间连续跟踪。距离先显示区域关系，不把像素直接标成厘米。真实地面距离估计属于后续标定功能。

跌倒事件出现后提供明确提示与人工求助入口，不以人为设定的等待时间阻塞求助。起身不自动证明无伤。演示不得要求实际摔倒；动态过程使用来源与使用权限明确的测试素材。

## 4. 环境监测模块

| 功能 | 输入 | 当前实现 | 对决策的影响 |
| --- | --- | --- | --- |
| 温度 | 温度、单位、更新时间 | 数值卡片、短趋势、模拟滑块 | 超出演示范围可产生环境关注与提醒 |
| 湿度 | 相对湿度、单位、更新时间 | 数值卡片、短趋势、模拟滑块 | 超出演示范围可产生环境关注与提醒 |
| 烟雾报警器状态 | normal / alarm / fault / offline / unknown | 独立状态卡、模拟报警开关 | alarm 进入紧急事件分支，不等待视觉确认 |
| 燃气报警状态 | normal / alarm / fault / offline / unknown | 可选模拟卡片 | 有效报警进入预设紧急分支；不能由普通摄像头确认泄漏 |
| 门磁状态 | open / closed / unknown | 可选模拟开关或以后接入硬件 | 可作为越线事件的辅助证据，不能识别人是否外出 |
| 设备健康 | 在线、最后更新时间、错误原因 | 软件检测状态，外接设备未接入时标明 | 产生设备故障事件，不能继续报告监测正常 |

普通电脑摄像头不能直接测得室内温湿度、烟雾浓度或燃气浓度。没有测量来源时，不展示伪造的 ppm、温度或真实报警器在线状态。

温湿度范围与持续时间是原型演示配置，不宣称是医学安全阈值。一般舒适度偏离不直接进入限制或紧急求助。

烟雾报警是独立高优先级输入，不能被“画面没有烟”或“人物已离开”否定。原型不得承担真实消防报警职责，也不得延迟或关闭独立报警器。USFA 强调烟雾报警后的逃生时间可能很短，因此本方案不采用强制逐级等待。[USFA 烟雾报警说明](https://www.usfa.fema.gov/prevention/home-fires/prepare-for-fire/smoke-alarms/)

## 5. 个体能力档案

采用演示代号和可编辑能力预设，不由摄像头推断认知症程度。

- 是否理解简短语音：可理解 / 需配合视觉 / 未知。
- 是否需要视觉引导：需要 / 不需要 / 未知。
- 是否能完成约定手势、点击回应或主动求助。
- 行动支持需求、提醒偏好、熟悉区域及预设活动时间。
- 信息来源与更新时间。

能力只影响支持方式与可选动作，不改变已观测事实；不能因为“能力较强”忽略烟雾报警，不能把拒绝提示等同于无法理解或无行为能力。

## 6. 风险分级与干预选择分开

保留 L0—L4：L0 当前有效观测中未见目标异常、L1 关注、L2 需提醒、L3 高度关注、L4 紧急事件。等级是原型策略标签，不是医学诊断或发生危险的概率。

输入无效时标为 UNKNOWN，不能归为 L0。已经存在的事件也不能因输入断开而自动消失。

风险来自事件类型、持续证据、环境状态、历史变化与人工确认。不把六个任意权重的加权分数作为判断核心。保留可配置的场景条件、演示阈值及版本记录。

候选干预综合考虑：

`事件与风险等级 + 个体支持需求 + 患者反馈 + 上一次干预及结果 + 数据有效性 + 可用执行能力`

同一 L2 区域停留事件：理解简短语音的人可先 I1；需要视觉支持的人可直接 I2。该例是交互策略，不是临床处置标准。

“提醒未得到回应”可以增加支持强度，不必自动提升风险等级。没有新危险证据时，不能为了让界面升级而编造更高风险。

## 7. 渐进式干预决策引擎

| 标识 | 含义 | 当前网页能真实执行的内容 | 不能声称已经执行的内容 |
| --- | --- | --- | --- |
| I0 Observe | 观察 | 持续监测、记录事件，不主动打扰 | 无 |
| I1 Remind | 提醒 | 简短文字、提示音、可用时播放本地语音 | 未播放成功不能记为已提醒；不假定用户已听见 |
| I2 Guide | 引导 | 分步骤文字、较大图示、经人工预设的方向提示 | 不宣称生成了安全逃生路线；产品靠近、实体灯光均未执行 |
| I3 Restrict | 限制/保护动作请求 | 展示限制建议、模拟动作和执行能力状态 | 不宣称已关火、锁门、阻止患者或控制设备 |
| I4 Help | 求助 | 创建网页内的照护者待处理事件、突出警报、记录人工接手 | 不宣称手机已收到、家属已联系或紧急服务已呼叫 |

I0—I4 保留为干预类别与展示标识，不是必须按顺序走完的阶梯。求助可以在提醒或引导的同时发生，I3 不是 I4 的前置条件。

紧急事件允许直接触发 I4，并呈现适当的预设提示；不能先等待多轮提醒或限制动作。任何保护动作都不得妨碍逃生。原型不实施实际限制措施。

动作记录包含 action_type、requested_at、状态和结果。状态区分：requested / executed / simulated / failed / unavailable。未接执行器的动作只能标为 simulated 或 unavailable。

## 8. 患者反馈闭环

允许的反馈包括：观测到行为改变、人工确认已回应、请求帮助、明确拒绝、未收到反馈、无法判断。患者本人输入与演示者代填须区分。

摄像头可支持判断是否退出指定区域、姿态是否变化或是否完成约定手势；不能直接确认患者听懂、拒绝或无意识。没有语音识别能力时，不假装识别了口头回应。

普通事件示例：

1. 持续停留满足演示条件，产生 L2 事件。
2. 根据能力档案选择 I1 或 I2，记录实际执行状态。
3. 进入等待反馈，继续观察。
4. 退出区域且证据稳定：进入 RECOVERING，随后关闭该普通事件。
5. 未收到反馈但画面有效：重新评估，可能增加引导或生成照护者待处理请求。
6. 遮挡或输入无效：保留事件并显示无法判断，不当作成功或拒绝。

风险下降必须有相应证据。烟雾报警未解除时，人物离开不消除环境事件；疑似跌倒后恢复站立不自动判定安全。关闭提示音、确认接手、标记误报、结束事件分别记录。

## 9. 有限状态机

保留有限状态机，但避免把风险等级、事件阶段和干预等级存成相互竞争的三套高低状态。

建议采用：

- `risk_level`：L0—L4 或 UNKNOWN，表达当前事件风险判断。
- `event_state`：MONITORING / CONFIRMING / INTERVENING / WAITING_RESPONSE / ESCALATED / RECOVERING / CLOSED。
- `interventions`：当前选中或执行的 I0—I4 动作集合。
- `observation_status`：VALID / DEGRADED / UNKNOWN。
- `ack_status`：UNACKNOWLEDGED / ACKNOWLEDGED，表达是否有人接手。

| 当前阶段 | 事件条件 | 下一阶段 | 主要动作 |
| --- | --- | --- | --- |
| MONITORING | 出现待确认的普通异常 | CONFIRMING | 收集连续证据 |
| CONFIRMING | 满足场景条件 | INTERVENING | 选择并尝试执行干预 |
| INTERVENING | 提醒/引导成功呈现 | WAITING_RESPONSE | 记录反馈窗口 |
| INTERVENING | 动作失败或不可用 | ESCALATED | 显示失败并选择可用后续动作 |
| WAITING_RESPONSE | 收到有效改变证据 | RECOVERING | 观察是否稳定解除 |
| WAITING_RESPONSE | 超过演示反馈窗口 | INTERVENING 或 ESCALATED | 依据证据与历史重新选择，不机械加一级 |
| 任一未关闭阶段 | 紧急输入 | ESCALATED | 立即生成高优先级求助事件，允许并行提示 |
| RECOVERING | 普通事件稳定解除 | CLOSED | 结束该事件并继续监测 |
| RECOVERING | 异常再次出现 | CONFIRMING 或 ESCALATED | 按新证据重新判断 |

数据质量下降是独立状态，不直接触发 CLOSED。紧急事件由明确的关闭条件与人工处理流程结束。

原计划中的 SAFE、LOW_RISK、MEDIUM_RISK、HIGH_RISK、EMERGENCY 可以作为风险派生显示标签，不另存一套容易冲突的状态。SAFE 的页面文案使用“当前未见目标异常”，避免作绝对安全承诺。

## 10. 多事件与报警管理

- 每个事件独立记录类型、对象/区域、来源、风险、干预、反馈、状态与理由。
- 多事件同时存在时优先展示最高紧急程度，不能取平均值稀释烟雾等紧急输入。
- 同一次持续异常合并更新；提醒有节流和上限，避免按视频帧重复报警。
- 重复帧或重复消息不能重复执行同一动作；新一次事件或严重度变化可以重新通知。
- 一般提醒允许适度观察与确认；不能把等待机制用于阻塞紧急求助。
- 一条普通事件解除，不清空其他未解决事件。
- 演示时间与真实时间明确区分；视频回放使用视频时间，实时计时使用可靠时钟，不以处理帧数代替秒数。

## 11. 网页组成

1. 实时监测：画面、骨架、区域、跟踪与识别有效性。
2. 环境状态：温度、湿度、烟雾、可选燃气/门磁；始终展示来源和更新时间。
3. 风险与证据：各事件 L 等级、满足/未满足的条件、缺失信息。
4. 当前干预：I 类型、选择理由、执行状态、上一动作及结果。
5. 患者/照护者交互：回应、求助、接手、误报、结束处理。
6. 决策时间线：观察、触发、干预、反馈、升级、恢复，附状态变化。
7. 档案与演示面板：能力预设、区域配置、模拟传感器控制、阈值及版本。

开始监测时主动启用声音；浏览器拒绝播放时显示失败，不能只写入成功日志。摄像头仅在授权后启用；默认本地处理，不默认保存或上传原始视频。隐藏原始画面的“骨架显示模式”不等于没有采集图像。

## 12. 验收案例

至少覆盖以下结果，而不是只检查页面控件是否存在：

1. 正常经过不产生持续提醒；停留达到演示条件后才触发普通事件。
2. 同一风险、不同能力档案产生不同支持方式，并展示理由。
3. 提醒后离开普通关注区域，经过稳定确认后结束该事件。
4. 没有回应时重新评估；拒绝不自动触发强制限制。
5. 摄像头遮挡、断开或跟踪丢失不会自动解除事件。
6. 疑似跌倒测试同时覆盖弯腰、坐下、蹲下与主动躺下等反例，记录漏报、误报和检测延迟，不只展示成功片段。
7. 烟雾模拟报警可直接进入紧急分支，无人可见、能力较强或温湿度正常都不能压低它。
8. 页面和日志始终能识别模拟环境输入；传感器缺失不显示正常。
9. I3 未接硬件时不显示已完成；I4 未接外部通知时不显示已通知家属。
10. “关闭提示音”“有人接手”“事件关闭”互不混淆。
11. 多事件同时存在时，解除区域停留不会清除烟雾或疑似跌倒事件。
12. 同一持续事件不重复刷屏；恢复后新事件可以重新报警。
13. 更换场景或视频时正确重置跟踪状态，不混入上一段记录。
14. 测试素材与用于调参数的素材分开；报告测试条件和结果，不能宣称临床有效。

## 13. 后续扩展与明确不做

后续：真实环境传感器、手机推送、经过标定的地面距离估计、更多演员与机位的评估。通过输入适配器和通知适配器扩展，不改写事件核心。

当前不做：认知程度诊断、意识/伤情判断、真实火灾可靠性认证、自动锁门或限制人身活动、未经验证的动态逃生路线、真实紧急电话、隐蔽采集、无标注的假数据、从零训练大模型。
